Personal profile:

I am a 3D computer vision scientist with several years of industry experience and a strong background in camera sensors, optical imaging systems, and 3D photogrammetry. My work spans sensor calibration, multi-sensor integration, and 3D reconstruction, with a focus on building accurate, reliable imaging systems for practical applications.

I also develop AI infrastructure and optimized inference pipelines, including model deployment with TensorRT, custom kernel fusion, and TensorRT plugin development. Using C++, Python, and CUDA, I optimize models and algorithms for low-latency execution on hardware with limited computational resources.

My CUDA development experience covers 3D algorithms for ray tracing, mesh manipulation, mapping 2D segmentation results onto 3D geometry, and noise filtering. I use CUDA–OpenGL interoperability for real-time rendering, connecting GPU computation with interactive 3D visualization. Together, these skills allow me to build complete pipelines from image acquisition and reconstruction to AI inference and visualization.

3D Vision

2D segmentation vote → 3D photogrammetry

algorithm design

From photogrammetry to 3D segmentation. This workflow originally used photogrammetry to reconstruct a 3D mesh from captured images. The reconstruction stage has since been replaced by VGGT, as described in my Real time coached photogrammetry project.

Combining segmentation masks across views. After our 2D AI model segments all source images, the resulting masks are mapped onto the 3D mesh and combined through voting. This brings segmentation observations from multiple camera views together on a shared 3D surface.

CPU-built BVH with CUDA traversal. I implemented bounding volume hierarchy (BVH) construction on the CPU and traversal in custom CUDA kernels to accelerate mask-to-mesh mapping. A balanced hierarchy over 220 mesh elements has a depth of approximately 20 levels. Traversal prunes irrelevant branches, greatly reducing the number of candidate intersection tests compared with checking every mesh element.

AR Segmentation Mapping & Projection

visionOS: segmentation on 3D models. I mapped 2D AI segmentation results onto 3D models reconstructed through photogrammetry. The pipeline searches the photogrammetry image database for the closest matching view, aligns the segmentation result with that reference image, and uses camera intrinsics and extrinsics to ray-cast the aligned mask onto the 3D surface.

iPadOS: live AR overlays. I wrapped OpenCV image-matching algorithms for iPadOS to align segmentation results with the live ARKit camera view, allowing users to inspect segmentation overlays in real time.

Camera-projector system: real-time projection. I designed a camera-projector pair to project segmentation results onto physical surfaces. Modeling the camera and projector as a stereo pair allows image-matching results in the camera view to be remapped into projector coordinates for aligned, real-time projection.

AI Infra Deployment

Real time coached photogrammetry

Watch demo (Video) Inference pipeline (PDF) Deployment design (PDF)

The challenge: reconstruction from individual photos. The device has no IMU, no distance sensor, and no high-frame-rate camera. Users can only capture individual photographs by pressing a button, leaving the system without continuous motion or depth measurements to guide reconstruction.

Why conventional reconstruction falls short. In this workflow, traditional Structure-from-Motion (SfM) requires long processing times, so users cannot receive real-time reconstruction feedback as they capture photos. SIFT-based sparse point clouds are also difficult for users to interpret, while dense point-cloud reconstruction with the conventional pipeline cannot meet the workflow's real-time feedback requirements. The challenge is therefore to provide feedback that is both fast enough to guide capture and visually clear enough for users to understand.

Finding a promising approach at CVPR 2025. I learned about VGGT (Visual Geometry Grounded Transformer) at CVPR 2025. After discussing it with the authors, I saw its feed-forward approach as a strong fit for this challenge: it can rapidly estimate camera parameters and dense scene geometry from input images, providing camera poses and dense point clouds for the reconstruction workflow.

From reconstruction to guided scanning. The estimated camera poses and dense geometry provide a foundation for subsequently projecting 2D AI burn-segmentation masks onto the reconstructed surface. My goal was also to use rapid dense point-cloud updates to give users an intuitive view of scanning progress, helping them understand the reconstructed shape and decide where to capture additional photos.

Engineering challenges. Turning VGGT into an interactive application introduced four practical obstacles. The Python/PyTorch inference pipeline was too slow for our feedback loop and consumed too much GPU memory. The predicted point clouds required additional post-processing and better depth fusion across views. In addition, some operations relied on PyTorch-specific implementations that could not be automatically converted to TensorRT in our deployment pipeline.

Resolving TensorRT conversion blockers. Working with Akretz, I resolved the difficulty of expressing torch.cartesian_prod, used in the PyTorch implementation at the time, in TensorRT. I also resolved the dynamic-max normalization issue in RoPE positional embeddings, addressing another obstacle to deployment.

Splitting engines and sharing runtime memory. I separated VGGT into three TensorRT engines—the aggregator, camera head, and depth head—and removed the tracking head, which was unnecessary for this reconstruction workflow. To further reduce GPU memory usage, I used TensorRT's kUSER_MANAGED execution-context allocation strategy and setDeviceMemory to assign the same preallocated GPU memory buffer to each engine in turn during sequential inference, avoiding separate, dedicated runtime allocations for each execution context. I then ran my custom skin-mask model concurrently with the aggregator on a separate CUDA stream. A custom CUDA kernel combined the skin-mask predictions with depth confidence entirely on the GPU, so the depth output was already filtered by the skin mask when VGGT prediction completed, without additional CPU–GPU communication for this filtering step. I also ran the depth head in batches of four frames instead of processing all frames at once, reducing peak GPU memory usage.

GPU depth fusion with TSDF. Once depth prediction completed, I used truncated signed distance function (TSDF) fusion to integrate depth estimates across frames, reducing gaps between their point clouds and producing a more continuous reconstruction. I transferred the depth data directly from CUDA into an Open3D Image tensor on the GPU, avoiding a round trip through CPU memory and reducing data-transfer overhead in the post-processing pipeline. After post-processing, I passed the point cloud directly to OpenGL for rendering through an OpenGL buffer registered with CUDA, keeping the rendering data on the GPU.

Mesh reconstruction and full-resolution texturing. I reconstructed a mesh from the TSDF-fused point cloud, then performed GPU-based UV mapping and texturing using images at each camera's original resolution. While our VGGT inference pipeline used 518 × 518 images, texturing from the original captures preserved finer surface detail and improved mesh texture quality.

10-Model Burn Ensemble Deployment on Jetson with TensorRT

I deployed an ensemble of 10 burn-analysis models on NVIDIA Jetson AGX Orin using TensorRT, optimizing model loading and memory usage for on-device inference.

Concurrent loading. I implemented concurrent model loading with CUDA streams.

Runtime memory reuse. I optimized memory allocation so that each model could reuse runtime memory from previously executed models, reducing the ensemble's memory footprint.

JetPack compatibility. I selected a JetPack version compatible with the models and TensorRT deployment stack.

Inference performance. After deployment optimization, inference time decreased from 27 seconds in the AWS A100 setup to 2 seconds on Jetson AGX Orin.
